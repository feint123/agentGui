# 能力发现、引导与内建帮助需求说明

日期：2026-03-10

关联对象：README、设置页、技能系统、工具系统、工作流系统、首次使用体验

## 1. 背景

agentGui 现在已经不是单一聊天窗口，而是一个包含工具、技能、子代理、工作流、创作记忆和块编辑器的复杂客户端。但应用内对于这些能力的解释和引导仍然不足，导致用户必须依赖 README、docs 或试错来理解产品边界。

当前主要问题：

- 设置页更像参数表单，不像能力入口
- 缺少首次启动引导
- 缺少“当前可以做什么”的能力清单
- 缺少失败后的自助诊断与帮助入口

## 2. 目标

把 agentGui 从“需要读文档才能上手”的工具，升级为“应用内可自我解释”的产品。

## 3. 不在本次范围

- 不做营销官网
- 不做视频教程系统
- 不做完整社区中心

## 4. 功能点

### 功能点 1：首次使用引导

需求：

- 首次启动时引导用户完成 API Key、模型选择、工作区、基础工具权限配置
- 明确区分“普通聊天模式”“Agent 工具模式”“工作流模式”“创作记忆模式”
- 提供最小可用示例，而不是只让用户面对空白输入框

### 功能点 2：能力浏览器

需求：

- 在应用内展示当前可用的模型、工具、技能、工作流和创作能力
- 每项能力需说明：用途、适用场景、限制、风险、是否已启用
- 用户可以从这里直接跳到配置、试用或查看示例

### 功能点 3：上下文帮助系统

需求：

- 在消息区、工具卡片、工作区、设置页提供就近帮助入口
- 对复杂能力如 Bash、工作流、Story Memory、技能系统提供简明说明
- 帮助内容需和当前状态相关，而不是一篇统一长文

### 功能点 4：失败诊断与自助排障

需求：

- 当 API 未配置、工具未启用、权限被拒绝、工作流暂停、数据恢复失败时，界面需给出下一步建议
- 失败提示不能只显示原始错误字符串
- 需要提供“查看详情”和“如何修复”两层信息

### 功能点 5：示例任务与模板入口

需求：

- 为常见任务提供示例：代码审查、文档总结、运行测试、生成计划、写作辅助
- 可从首页、空状态或帮助中心直接启动
- 示例应体现 agentGui 的差异化能力，而不是泛泛聊天示例

## 5. 交互要求

- 帮助入口必须就近可见，不能全部塞进 README 或菜单深处
- 引导文案应简洁、任务导向，避免只讲概念
- 用户在遇到失败时，应优先看到“怎么继续”，而不是只看到“失败了”

## 6. 验收标准

- 新用户首次进入应用时，可在 3 分钟内完成基础配置并跑通第一个任务
- 用户可以在应用内看到当前启用的工具、技能和工作流清单
- 关键失败场景存在明确修复建议
- 空状态页能引导用户启动至少 3 类典型任务

## 7. 优先级

- P0：首次使用引导、失败诊断
- P1：能力浏览器、上下文帮助
- P2：示例任务模板与更细的引导编排
