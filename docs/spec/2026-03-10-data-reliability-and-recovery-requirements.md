# 数据可靠性与故障恢复需求说明

日期：2026-03-10

关联对象：`AppSettings`、`Session`、`ExecutionPlan`、`ClaudeService+TodoTool`、`ClaudeService+ExecutionPlan`、`WorkflowRuntime`、SwiftData 持久化路径

## 1. 背景

当前项目已经把会话、消息、工具调用、AgentRound、WorkflowInstance 等核心记录落到 SwiftData，但数据层仍停留在“能写入”的阶段，还没有形成面向长期使用的可靠性体系。

几个典型问题已经比较明确：

- 多处持久化路径仍使用 `try? modelContext.save()`，错误会被静默吞掉
- `sessionTodoLists`、`sessionVerifications` 仍是内存态，应用退出后丢失
- 执行计划、验证记录、工作流快照之间缺少统一恢复语义
- 缺少模型版本迁移、损坏检测、导出备份与恢复入口

如果继续在现有基础上叠加功能，用户会先遇到“数据不可信”问题，而不是“功能不够多”问题。

## 2. 目标

建立一套覆盖保存、恢复、迁移、备份和告警的可靠性框架，让 agentGui 可以被视为“可信的长期工作记录器”，而不是仅依赖当前进程内状态的实验型客户端。

## 3. 不在本次范围

- 不重写整个 SwiftData 数据层
- 不引入云同步或多设备同步
- 不处理团队协作冲突合并

## 4. 功能点

### 功能点 1：统一持久化保存策略

需求：

- 所有 SwiftData 保存路径统一走 `PersistenceCoordinator` 或等价封装
- 禁止在业务路径中直接散落 `try? modelContext.save()`
- 保存失败必须带有错误分类、错误日志和用户可见反馈策略

最低要求：

- 保存失败时能区分权限问题、磁盘空间不足、模型校验失败、数据库损坏
- UI 至少能提示“本次变更未成功保存”
- 对会话消息、工具调用、工作流记录三类核心数据启用更严格的失败告警

### 功能点 2：会话级任务状态持久化

需求：

- TodoList、CompletionVerification 不能只保存在内存字典里
- 会话的执行计划、验证结论、当前 Todo 状态需要可恢复
- 重启应用后，工作区侧栏应恢复上次任务态，而不是丢失

建议模型：

- 为会话建立 `SessionTaskState` 持久化对象，统一承载：计划、Todo、验证结果、最近更新时间
- 或将 Todo、Verification 升级为 SwiftData 模型并挂到 `Session`

### 功能点 3：异常中断恢复

需求：

- 应用意外退出后，能够识别哪些会话或工作流在上次运行时未正常结束
- 对未完成任务展示“恢复查看”“标记为中断”“清理现场”三类入口
- 对进行中的 Bash 任务、Workflow 任务、未完成消息生成分别建立恢复状态

### 功能点 4：数据完整性检查

需求：

- 启动时执行轻量级完整性检查
- 检查对象包括：孤立 Message、缺失 Session 的 ToolCall、损坏的 plan JSON、非法 workflow 记录
- 检查结果需要进入诊断面板，而不是只打日志

### 功能点 5：模型迁移与版本管理

需求：

- 为关键模型引入 schema version 概念
- 每次结构变更都必须记录迁移策略和回滚策略
- 文档中明确哪些字段允许废弃，哪些字段需要兼容旧版本数据

当前实现约束：

- 当前持久化 schema version 为 `1`，由应用集中常量维护，备份 manifest 与关键模型共享同一版本语义
- `BackupArchiveManifest.schemaVersion` 是当前迁移边界的权威入口；恢复流程必须先校验版本，再进入 dry-run / 实际写入
- `SessionTaskState` 的归档载荷对缺省字段保持向后兼容：旧载荷缺少 `todoJson`、`verificationJson`、`updatedAt` 时，应分别回退到 `[]`、空字符串和当前时间
- 回滚策略采用“拒绝不兼容版本恢复”而不是静默降级，避免半恢复状态
- 允许兼容旧字段：`Session.planJson` 作为 legacy 字段继续保留，并由 `SessionTaskState` 承接统一任务态

### 功能点 6：备份、导入与灾难恢复

需求：

- 提供应用级导出备份能力，至少覆盖会话、消息、工作流、设置
- 支持从备份包恢复到新安装环境
- 支持只导出单个会话和导出完整数据快照两种模式

## 5. 交互要求

- 当保存失败时，不能只在控制台打印日志
- 当发现损坏数据时，不能直接崩溃或静默跳过
- 当存在可恢复任务时，用户进入会话后应看到明确的恢复提示

## 6. 验收标准

- 关闭应用再重启后，会话计划、Todo 和验证状态可恢复
- 人为制造保存失败时，用户可见明确错误提示，且不会误以为保存成功
- 损坏的 JSON 计划或不完整的工作流记录能够被识别并提示修复
- 提供一条可执行的全量备份与恢复路径

## 7. 优先级

- P0：统一保存策略、任务状态持久化、异常中断恢复
- P1：完整性检查、备份与恢复
- P2：精细化迁移框架与诊断报告
