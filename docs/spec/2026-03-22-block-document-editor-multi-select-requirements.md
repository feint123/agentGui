# 2026-03-22 BlockDocumentEditor 拖拽框选多选与块级上下文菜单需求文档

日期：2026-03-22

状态：需求草案

关联对象：`BlockDocumentEditor`、`BlockRowView`、`BlockTextEditor`、`BlockEditorModels`、`BlockEditorUndoModels`、`BlockEditorMutationDriver`、`BlockMarkdownCodec`、`FileEditorView`

## 0. 文档结论

`BlockDocumentEditor` 目前已经具备块级文档模型、块重排、块插入、块删除、内联文本选区、Slash 命令和 Undo/Redo 基础能力，但仍停留在“单块编辑器”的交互层级。

这导致两个直接问题：

1. 用户无法像现代块编辑器那样，通过拖拽框选一次选中多个块做批量操作。
2. 用户即使已经在视觉上识别出多个目标块，也没有统一的块级上下文菜单来执行剪切、复制、复制为 Markdown、复制为纯文本、复制为 HTML 等高频动作。

因此，这次需求不应理解为“加一个右键菜单”或“临时做个多选状态”，而应升级为一套完整的块级选择系统：

1. 为 `BlockDocumentEditor` 增加独立于内联文本选区的块级多选模型。
2. 为块级多选增加拖拽框选、点击选择、范围扩选与清空行为。
3. 为块级多选建立统一命令层，承接右键菜单、快捷键、主菜单和未来工具栏入口。
4. 为复制与剪切建立可扩展的序列化管线，而不是把 Markdown、纯文本、HTML 转换散落在 View 层。

一句话概括本次需求：

> 把 `BlockDocumentEditor` 从“只能逐块操作的编辑器”升级为“具备块级多选、批量命令和可扩展导出能力的现代块编辑器”。

## 1. 当前代码现状与问题

## 1.1 当前只有单块内联选区，没有块级选区

现有编辑器的选区能力由 `InlineSelectionState` 驱动，核心语义是：

1. 某一个 `blockID` 内部的文本范围。
2. 对应屏幕坐标上的文字选区矩形。
3. 行内样式工具栏可执行的动作集合。

这套模型适用于“加粗、斜体、行内代码”等文本级操作，但不能表达：

1. 多个块被同时选中。
2. 主选中块与附加选中块。
3. 拖拽框选过程中的临时命中集合。
4. 针对多块的上下文菜单和批量命令。

结论：块级选区必须有独立数据模型，不能继续复用内联文本选区。

## 1.2 当前交互层存在潜在冲突

`BlockDocumentEditor` 已经支持：

1. `NSTextView` 内联文字选中。
2. 块拖拽重排。
3. 外部文件拖入。
4. 点按空白区域收起浮层。

如果直接在当前视图上粗暴叠加拖拽框选手势，会与以下行为冲突：

1. 文本编辑区域中的原生文字选择。
2. 已存在的块重排行为。
3. 链接、文件、图片等资源块的点击激活语义。

结论：拖拽框选必须明确起手区域、状态优先级和冲突消解策略，不能依赖模糊的手势竞争。

## 1.3 当前没有块级命令抽象

`BlockEditorMutationDriver` 能记录变更，`BlockMarkdownCodec` 能序列化整个文档，但缺少：

1. “对选中块集合执行命令”的统一入口。
2. “将选中块导出成不同格式”的统一策略层。
3. “同一命令既能给右键菜单，也能给快捷键/主菜单”的复用接口。

结论：必须先定义块级命令系统，再让上下文菜单成为其一个入口，而不是反过来。

## 2. 目标

本次需求目标如下：

1. 支持通过拖拽框选选中多个块。
2. 支持通过点击、Shift 扩选、Command 切换补充块级多选能力。
3. 右键点击块或多选区域时，弹出块级上下文菜单。
4. 第一批菜单动作至少包括：剪切、复制、复制为 Markdown、复制为纯文本、复制为 HTML。
5. 同时补齐一组与多选强相关、用户高频需要的补充动作，避免后续菜单语义破碎。
6. 保证实现具备模块化、可测试、可扩展的结构，便于后续增加更多批量操作。

## 3. 非目标

本期不包含以下内容：

1. 不实现跨窗口或跨文档的块级拖放搬运。
2. 不在第一期内实现 Figma/Omni 风格的任意自由区域套索选择，只支持矩形框选。
3. 不在第一期内重做整套块渲染视觉语言。
4. 不在第一期内支持“部分文本 + 部分块”的混合多选。
5. 不在第一期内为每一种块类型都提供专属批量转换器。

## 4. 方案比较

### 方案 A：仅在右键时临时推断“相邻块集合”

优点：

1. 实现快。
2. 短期内能拼出少量批量操作。

缺点：

1. 没有显式选区，用户缺乏可见反馈。
2. 快捷键、菜单栏、工具栏无法共享同一套状态。
3. 后续增加拖拽框选时必然推翻。

### 方案 B：在 `BlockDocumentEditor` 内建立独立的块级选择系统

优点：

1. 交互、命令、序列化、Undo/Redo 可以围绕同一模型展开。
2. 右键菜单只是命令入口之一，设计可扩展。
3. 能兼容后续“批量移动、批量缩进、批量转换、批量 AI 操作”等功能。

缺点：

1. 首期设计工作更多。
2. 需要明确与现有内联选区、拖拽重排的边界。

### 推荐

推荐采用方案 B。

原因很直接：用户要的不是一次性菜单，而是现代块编辑器应有的块级操作能力。如果继续做局部补丁，后续每个批量能力都会重复发明状态管理。

## 5. 核心交互模型需求

## 5.1 选区层级必须显式分离

编辑器必须区分以下三种互斥状态：

1. `caret`：仅有光标，无文本选区、无块选区。
2. `inlineSelection`：单块文本选区激活，用于行内样式操作。
3. `blockSelection`：块级单选或多选激活，用于批量操作。

要求：

1. 激活 `blockSelection` 时，必须清除当前内联文本选区浮层。
2. 进入 `inlineSelection` 时，必须清除当前块级多选高亮。
3. 不允许界面同时显示行内工具栏和块级多选命令态。

## 5.2 块级选区的数据语义

块级选区模型至少需要表达：

1. `selectedBlockIDs`：当前选中的块集合。
2. `primaryBlockID`：主选中块，用于焦点、锚点和菜单上下文。
3. `anchorBlockID`：范围扩选锚点。
4. `selectionSource`：点击、Shift 扩选、Command 切换、拖拽框选、键盘选择。
5. `marqueeRect`：拖拽框选进行中的矩形区域。

要求：

1. 块级选区必须与 `DocumentBlock.id` 对齐，不能使用 index 作为长期标识。
2. 任何块插入、删除、重排后，选区都要按 `id` 重新映射。
3. 命令层读取选区时，不得直接依赖 View 遍历顺序。

## 5.3 点击选择行为

要求如下：

1. 单击块外缘选择区或块容器背景时，选中该块并清除其他块选择。
2. `Command + 点击` 时，对目标块执行加入或移出当前选择集合。
3. `Shift + 点击` 时，以锚点块与当前块之间的文档顺序范围建立连续多选。
4. 点击编辑器空白区域时，清空块级选区。
5. 当右键点击发生在已选集合内部时，不应重置选区。
6. 当右键点击发生在未选中块上时，应先将选区切换为该块，再弹出菜单。

## 5.4 拖拽框选行为

第一期要求支持矩形框选，且必须避免与文本选中冲突。

推荐交互约束：

1. 拖拽框选仅允许从块左侧选择带、块间空隙或编辑器留白区域发起。
2. 在 `NSTextView` 正文区域内拖拽，仍保留原生文本选中行为，不抢占事件。
3. 框选命中的判断标准为“块容器矩形与选择框相交”。
4. 框选过程中必须实时高亮命中块。
5. 松手后生成最终块级选区，并设定主选中块。
6. `Command + 拖拽框选` 时，可在现有集合上做并集补充。
7. `Option + 拖拽框选` 不在第一期定义特殊语义，避免过度设计。

## 5.5 与块拖拽重排的冲突规则

要求：

1. 块重排的拖拽入口必须与框选入口分离。
2. 若当前手势从重排拖拽把手发起，应进入重排，不进入框选。
3. 若当前已有多选集合，拖动重排把手不在第一期内支持“整组拖动”；第一期保持单块重排语义。
4. 多选态下若用户尝试拖动正文区域，不应意外触发块重排。

结论：框选与重排必须是两个独立入口，否则稳定性会很差。

## 6. 上下文菜单需求

## 6.1 菜单触发规则

要求：

1. 单选块时右键弹出块级菜单。
2. 多选块时右键弹出多选菜单。
3. 菜单标题和文案要能反映当前选择规模，例如“复制 3 个块”。
4. 对不可用动作必须置灰，而不是点击后提示失败。

## 6.2 第一期开箱即用动作

以下动作列为 P0，必须在首版进入需求范围：

1. 剪切
2. 复制
3. 复制为 Markdown
4. 复制为纯文本
5. 复制为 HTML
6. 重复
7. 删除
8. 全选块
9. 取消选择

说明：

1. “复制”默认应写入最适合编辑器内外通用粘贴的多格式剪贴板，而不是只写 Markdown。
2. “复制为 Markdown / 纯文本 / HTML”是明确导出动作，应始终写入用户指定格式。
3. “重复”是高频批量操作，应与复制/剪切/删除一起作为基础块命令进入首期。

## 6.3 第二期候选动作

以下动作不要求首版落地，但需求文档必须预留扩展位：

1. 粘贴到块前
2. 粘贴到块后
3. 批量转换块类型
4. 批量缩进/取消缩进
5. 折叠/展开所选折叠块
6. 复制为 JSON 或内部块格式
7. 发送到聊天输入区 / 作为上下文引用
8. 导出所选块为独立文件

## 6.4 快捷键与主菜单对齐

要求：

1. 当块级选区激活时，`Command + X` 执行剪切。
2. 当块级选区激活时，`Command + C` 执行复制。
3. 当块级选区激活时，`Delete` 执行删除。
4. 当块级选区激活时，`Escape` 清空块级选区。
5. 当块级选区激活时，`Command + A` 的行为需要可配置：
   1. 若焦点仍在某个文本编辑器中，保留原生全文字选择。
   2. 若焦点位于块级容器层，则执行“全选块”。

结论：命令定义不能只在右键菜单里存在，必须通过统一命令路由支撑快捷键与主菜单。

## 7. 复制、剪切与序列化需求

## 7.1 复制语义

`复制` 必须输出多表示形式的剪贴板内容，至少包括：

1. 内部块格式：供未来编辑器内高保真粘贴使用。
2. Markdown：供外部 Markdown 编辑器、聊天、文档系统使用。
3. 纯文本：供终端、输入框、简易文本环境使用。
4. HTML：供富文本目标粘贴时使用。

要求：

1. 若系统粘贴目标支持 HTML，应优先使用 HTML。
2. 若只支持普通字符串，应回退到纯文本或 Markdown。
3. 内部块格式必须为后续“保留块类型粘贴”预留 UTI 或自定义 pasteboard type。

## 7.2 剪切语义

`剪切` 应等价于：

1. 对当前选区先执行复制。
2. 复制成功后删除选中块。
3. 删除后把焦点移动到合理位置。

要求：

1. 若复制失败，不得继续删除。
2. 剪切应作为一个可撤销的原子命令写入历史。
3. 剪切后应自动选中删除位置附近的合理后继块，或回到空文档默认块。

## 7.3 各格式内容定义

### Markdown

要求：

1. 复用 `BlockMarkdownCodec` 的块文档序列化能力。
2. 多块导出时保持原有顺序。
3. 块之间的换行规则必须与全量文档导出保持一致。

### 纯文本

要求：

1. 纯文本以用户可读为首要目标，而不是机械拼接原始 Markdown。
2. 标题、列表、待办、引用、代码、表格等应有最小可读降级格式。
3. 资源块至少输出标题、路径或链接文本，而不是空白。

### HTML

要求：

1. 采用新的块级 HTML 序列化器，不能把 Markdown 先转字符串再粗暴包一层 `<pre>`。
2. 输出必须是结构化 HTML 片段，而不是完整文档壳。
3. 需要保证基础语义标签正确，例如标题、列表、引用、代码块、表格。

## 8. 架构与模块化要求

## 8.1 模块拆分原则

这次需求必须避免把所有逻辑继续堆进 `BlockDocumentEditor.swift`。

推荐最小拆分如下：

1. `BlockSelectionState`：块级选区数据模型。
2. `BlockSelectionCoordinator`：点击、扩选、清空、框选命中计算。
3. `BlockSelectionMarqueeOverlay`：框选矩形与命中高亮渲染。
4. `BlockContextMenuAction` / `BlockContextMenuFactory`：菜单声明层。
5. `BlockSelectionCommandRouter`：命令入口，供右键菜单、快捷键、主菜单复用。
6. `BlockSelectionClipboardWriter`：多格式剪贴板写入。
7. `BlockSelectionSerializer`：Markdown、纯文本、HTML、内部块格式导出。
8. `BlockSelectionMutationHandler`：剪切、重复、删除等会修改文档的操作。

要求：

1. View 层只负责展示和转发事件。
2. 命令层不直接依赖 SwiftUI View 生命周期。
3. 序列化与剪贴板写入不应散落在多个菜单回调里。

## 8.2 与现有运行时模型的集成要求

当前 `BlockEditorRuntimeState` 和 `BlockEditorSelectionSnapshot` 只覆盖单块文本选区。

本次需求要求：

1. 为运行时状态新增块级选区快照能力。
2. 明确块级选区与内联选区是并列语义，而不是互相覆盖的同一字段。
3. Undo/Redo 后，若文档结构仍能映射选中块，应尽可能恢复块级选区。
4. 删除、重复、剪切、粘贴等批量命令必须经过统一 mutation driver，保证历史记录完整。

## 8.3 可扩展性要求

架构必须保证未来增加以下能力时不需要推翻当前设计：

1. 多块拖动移动。
2. 多块复制后内部高保真粘贴。
3. 多块批量转类型。
4. 多块发送到 AI 操作链路。
5. 多块作为独立导出片段。

## 9. UI 与反馈要求

## 9.1 选中态可视反馈

要求：

1. 每个被选中的块必须有明确的容器级高亮。
2. 主选中块与附加选中块需要有轻微差异，便于用户识别锚点。
3. 框选中的临时命中态应与最终选中态区分，但视觉差异不宜过强。
4. 多选计数应在合适位置可见，例如上下文菜单标题、状态条或悬浮操作条。

## 9.2 空文档与单块场景

要求：

1. 文档只有一个块时，块级单选也必须成立。
2. 空白区域不足时，仍应允许通过块外缘或选择带进行框选起手。
3. 若文档滚动中进行框选，允许后续版本支持自动滚动；第一期可不做，但要预留设计位。

## 9.3 可访问性

要求：

1. VoiceOver 需要能读出“已选择 N 个块”。
2. 上下文菜单项应有明确中文文案与辅助说明。
3. 键盘用户必须能在不依赖鼠标的情况下触发基础批量命令。

## 10. 状态一致性与边界条件

## 10.1 结构变更后的选区修复

要求：

1. 若选中块被删除，系统应自动收敛到最近仍存在的块。
2. 若部分选中块被删除，其余仍存在块必须保留选中。
3. 若重排导致块顺序变化，选区集合按 `id` 保持，不按旧 index 错乱。

## 10.2 与外部文本同步的关系

要求：

1. 外部文本刷新导致整个 `BlockDocument` 重建时，应清空无效块级选区。
2. 若能根据块 `id` 或稳定映射恢复，则可恢复；否则必须安全降级为无选区。
3. 不允许保留悬空 `blockID` 导致菜单、快捷键或序列化访问越界。

## 10.3 与只读块类型的关系

要求：

1. 图片、文件、链接卡片、分隔线等非富文本块也必须能进入块级多选。
2. 即使某些块不支持内联编辑，也必须支持复制、剪切、删除等块级操作。
3. 菜单动作的可用性应根据“块级命令是否支持此集合”决定，而不是简单按块类型一刀切。

## 11. 验收标准

以下为首期验收标准：

1. 用户可以通过拖拽矩形框选一次选中多个块。
2. 用户可以通过 `Command + 点击` 增减选区，通过 `Shift + 点击` 做连续扩选。
3. 多选时有稳定可见的高亮反馈。
4. 右键菜单可对当前选区执行剪切、复制、复制为 Markdown、复制为纯文本、复制为 HTML、重复、删除、全选块、取消选择。
5. `Command + C`、`Command + X`、`Delete`、`Escape` 在块级选区激活时行为正确。
6. 剪切、重复、删除均支持 Undo/Redo。
7. 复制导出的 Markdown、纯文本、HTML 顺序正确、内容可读。
8. 拖拽框选不会破坏正文中的原生文本选中。
9. 框选与块重排不会互相误触。

## 12. 测试要求

## 12.1 单元测试

至少覆盖：

1. 点击单选、Command 切换、Shift 范围扩选。
2. 框选命中计算与并集补充。
3. 删除、重复、剪切后的选区修复。
4. Markdown、纯文本、HTML 导出结果。
5. 剪切失败时不删除。

## 12.2 集成测试

至少覆盖：

1. 块级多选与 Undo/Redo 链路。
2. 块级多选与现有 `BlockEditorMutationDriver` 的集成。
3. 块级多选与外部文本刷新同步。

## 12.3 UI 测试

至少覆盖：

1. 拖拽框选多个块。
2. 右键菜单出现并可执行基础动作。
3. 块多选与文本选中不互相抢焦点。

## 13. 开放问题

以下问题可以在进入实现前最终拍板，但不阻塞本需求文档成立：

1. 第一版是否需要显示块左侧“选择带”或“拖拽把手”，还是仅靠容器热区承载块选择入口。
2. `Command + A` 在编辑器聚焦态下默认优先“全选文本”还是“全选块”，需要结合主菜单与用户心智再定。
3. HTML 导出是否要在首版就覆盖所有资源块的富语义表示，还是先做可读降级。
4. 第二期是否要支持“复制后在同编辑器内粘贴为原始块结构”。

## 14. 推荐的实施顺序

为了控制风险，推荐按以下顺序实施：

1. 先引入块级选区模型与命令路由。
2. 再实现点击选择、Shift/Command 扩选。
3. 再实现框选层与命中计算。
4. 然后接入上下文菜单与快捷键。
5. 最后补齐复制序列化、剪贴板写入、Undo/Redo 与 UI 测试。

这样可以先把状态机打稳，再叠加手势和菜单，避免把问题全部堆到最后一起爆发。
