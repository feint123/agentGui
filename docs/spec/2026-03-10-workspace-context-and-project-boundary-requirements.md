# 工作区上下文与项目边界需求说明

日期：2026-03-10

关联对象：`WorkspacePanelView`、`WorkspaceState`、`Session.workingDirectory`、`AppSettings.workingDirectory`、文件树、当前选中文件与工作流上下文

## 1. 背景

当前项目已经具备文件树面板、工作目录选择、文件编辑器、工作流上下文采集等基础能力，但“工作区”仍然主要是一个全局路径设置，而不是会话和任务的一等上下文。

典型问题：

- `Session` 已定义 `workingDirectory`，但工作区面板仍主要依赖 `AppSettings.workingDirectory`
- 会话、工作区、当前文件、当前选区之间的绑定关系不完整
- 缺少最近工作区、工作区切换历史、工作区摘要和工作区安全边界联动
- 工作流和普通对话对工作区的理解还没有统一数据模型

## 2. 目标

把工作区从“一个目录路径”升级为“会话级项目上下文”，让用户在多项目、多会话和多任务场景下保持明确边界。

## 3. 不在本次范围

- 不做 VS Code 级别的多根工作区解析
- 不实现 Git 完整客户端
- 不把文件树扩展成 IDE 全功能项目管理器

## 4. 功能点

### 功能点 1：会话级工作区绑定

需求：

- 每个会话可以显式绑定自己的工作区根目录
- 未绑定时才回退到全局默认工作目录
- 会话切换时，文件树、活动文件、工具默认路径、工作流上下文要同步切换

### 功能点 2：工作区状态模型统一

需求：

- 统一管理以下状态：工作区根目录、当前选中文件、当前文本选区、最近访问文件、最近命令上下文
- 普通对话和工作流都从同一份工作区快照读取上下文
- 工作区上下文应可序列化，便于恢复与调试

### 功能点 3：最近工作区与快速切换

需求：

- 记录最近打开的工作区
- 支持从历史中快速切换并绑定到当前会话
- 在切换工作区时提示是否同步修改该会话的目录边界

### 功能点 4：项目边界感知

需求：

- 工作区面板应能识别 Git 仓库根、Xcode 项目、Package.swift、docs 目录等关键信号
- 在 UI 中展示项目摘要：根目录、仓库名、主要技术栈、关键入口文件
- 为 agent 工具提供更稳定的项目边界信息

### 功能点 5：会话与工作区联动导航

需求：

- 支持从消息、工具调用、工作流产物跳转到相关文件
- 支持显示“本会话最近访问的文件”与“本会话编辑过的文件”
- 当会话没有绑定工作区时，相关工具和 UI 要给出明确提示

### 功能点 6：工作区切换保护

需求：

- 正在运行的 Bash 任务、工作流任务、未保存编辑存在时，切换工作区需要二次确认
- 切换后，旧工作区相关后台任务状态不能被直接丢弃

## 5. 交互要求

- 工作区路径必须在界面中持续可见，而不是只在设置页出现
- 当前会话是否绑定独立工作区要可辨识
- 文件树与会话上下文切换时不能让用户感到“路径突然变了但不知道为什么”

## 6. 验收标准

- 两个不同项目的会话切换时，工作区根目录能稳定跟随切换
- 工作流启动时能读取到正确的会话工作区、活动文件和选区信息
- 最近工作区历史可用，且支持快速重绑定
- 切换工作区时能正确处理正在运行的任务和未保存状态

## 7. 优先级

- P0：会话级工作区绑定、工作区状态统一
- P1：最近工作区、导航联动、项目摘要
- P2：切换保护与高级边界提示
