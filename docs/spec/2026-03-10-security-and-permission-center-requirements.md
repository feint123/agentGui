# 安全、密钥与权限中心需求说明

日期：2026-03-10

关联对象：`AppSettings`、`ClaudeService`、`ClaudeService+ToolBuilder`、`ClaudeService+BashTool`、`ClaudeService+TextEditorTool`、Web 工具、子代理与工作流

## 1. 背景

agentGui 已经具备文件编辑、Bash、Web 抓取、子代理和工作流能力。这意味着它不再是单纯的聊天客户端，而是具有执行能力的本地 agent 容器。到了这个阶段，安全模型必须从“开关配置”升级为“权限中心”。

当前主要短板：

- `AppSettings.apiKey` 仍以普通字段保存
- 工具启用逻辑主要是全局布尔开关
- 不同风险等级的命令和文件操作尚未形成统一审批模型
- 缺少用户可理解的授权历史与风险追踪

## 2. 目标

建立“密钥安全 + 权限策略 + 风险分级 + 授权回放”的统一安全层，让 agentGui 在保持 agent 自动化能力的同时具备可控边界。

## 3. 不在本次范围

- 不实现企业级 SSO 或团队权限体系
- 不做远程设备管理
- 不替代操作系统原生沙盒机制

## 4. 功能点

### 功能点 1：密钥与敏感配置安全存储

需求：

- API Key、代理认证信息、未来的第三方服务令牌必须迁移到 Keychain
- `AppSettings` 只保留引用状态和非敏感偏好，不直接保存明文密钥
- 支持密钥校验、替换、清除和失效提示

### 功能点 2：统一权限中心

需求：

- 引入权限中心页面，统一管理 Bash、文件写入、Web 获取、子代理、工作流等能力
- 支持三层权限模型：全局默认策略、会话级策略、单次执行策略
- 对主代理、子代理、工作流角色分别配置权限边界

### 功能点 3：风险分级与确认机制

需求：

- 对文件读、文件写、批量写、目录删除、命令执行、网络访问分别定义风险级别
- 高风险操作默认要求显式确认
- 对重复出现且安全的操作支持“本会话记住选择”

### 功能点 4：目录与资源边界控制

需求：

- 文件读写和命令执行需要基于工作区根目录、会话工作目录和白名单路径判定是否允许
- 对跨目录访问、家目录扫描、系统目录访问建立额外审批规则
- Web 工具需要支持域名白名单、黑名单和代理策略联动

### 功能点 5：授权记录与审计回放

需求：

- 每次敏感授权都记录：操作者、时间、工具、目标资源、用户选择
- 在会话内可查看最近授权记录
- 失败、拒绝、自动放行三类事件都应可追踪

### 功能点 6：安全模式预设

需求：

- 至少提供：只读模式、受限模式、默认模式、开发者模式
- 不同模式影响工具暴露、自动确认策略、风险阈值和工作流可用能力

## 5. 交互要求

- 用户必须知道“当前会话处于什么安全模式”
- 敏感确认对话框需要明确说明影响范围，而不是只展示原始命令
- 权限开关不能散落在多个页面，需要集中管理

## 6. 验收标准

- 敏感密钥不再以明文持久化到应用数据仓库
- 高风险工具调用会进入统一确认或拒绝路径
- 会话级权限策略可以覆盖全局默认值
- 用户可以追踪最近一次高风险授权的完整上下文

## 7. 优先级

- P0：Keychain、风险分级、统一确认机制
- P1：目录边界控制、授权审计
- P2：模式预设与细粒度策略模板
