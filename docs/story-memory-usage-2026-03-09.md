# agentGui 创作记忆使用说明

日期：2026-03-09

## 1. 什么是创作记忆

创作记忆是 agentGui 为小说写作场景增加的项目级结构化记忆层。

它专门保存以下内容：

- 角色资料与角色弧线
- 世界规则、地点设定、风格约束
- 章节、场景、时间线事件
- 伏笔与连续性问题

它和长期记忆不是同一套东西：

- `memory.md` 适合保存全局偏好、通用经验、跨任务习惯
- 创作记忆只保存某个故事项目的 canon 和运行时检索数据

当前实现中，创作记忆数据保存在应用的 SwiftData 存储中，不写入 `~/.agentgui/memory.md`。

## 2. 适用场景

创作记忆适合这些任务：

- 长篇小说或系列故事写作
- 多角色、多地点、多章节的连续写作
- 需要检查时间线、设定一致性、伏笔回收的创作任务
- 需要让 Agent 在多轮写作中持续引用角色状态和世界规则

如果只是记录你的个人偏好、常用提示词或跨项目习惯，仍然应使用长期记忆而不是创作记忆。

## 3. 如何启用

在设置页的「创作记忆」区块中：

1. 打开「启用创作记忆」
2. 按需要决定是否开启「自动抽取剧情事件」
3. 调整「Prompt 记忆预算」
4. 选择项目绑定模式

当前可用的绑定模式包括：

- `auto`：优先根据当前上下文自动选择活跃项目
- `session`：当前会话绑定优先
- `manual`：只使用手动绑定的项目

默认模式是 `auto`。

## 4. 创建并绑定创作项目

你可以通过两种入口进入项目管理界面：

- 设置页中的「管理创作项目」
- 聊天页工具栏中的「创作记忆」按钮或当前项目名按钮

在项目列表页中可以：

1. 输入项目标题和一句话梗概
2. 点击「创建项目」
3. 在项目详情中点击「绑定到当前会话」

如果当前会话还没有绑定任何项目，第一次创建项目时会自动把该项目附加到当前会话。

## 5. 运行时会发生什么

当满足下面两个条件时，Claude 才会使用创作记忆：

- `AppSettings.enableStoryMemory == true`
- 当前会话的 `activeWritingProjectId` 有效

此时系统会在主循环中按当前请求动态组装 story-memory prompt slice，而不是把整个项目内容原样拼到上下文里。

当前注入的主要片段包括：

- 当前写作目标
- 上一场景衔接
- 活跃角色卡片
- 适用世界规则
- 最近相关事件
- 未解决伏笔
- 风格指令

`Prompt 记忆预算` 会影响每类片段允许进入 prompt 的数量上限。

## 6. Claude 可调用的创作记忆工具

当前内置了 13 个显式 story-memory 工具：

- `story_memory_create_project`：创建新的创作项目
- `story_memory_attach_project`：把项目绑定到当前会话
- `story_memory_upsert_character`：创建或更新角色资料
- `story_memory_upsert_chapter`：创建或更新章节记录
- `story_memory_upsert_scene`：在已有章节下创建或更新场景记录
- `story_memory_upsert_world_rule`：创建或更新世界规则
- `story_memory_upsert_location`：创建或更新地点档案
- `story_memory_upsert_foreshadow`：创建或更新伏笔与其状态
- `story_memory_upsert_style_profile`：创建或更新项目级风格档案
- `story_memory_update_continuity_issue`：更新连续性问题的处理状态
- `story_memory_append_event`：追加时间线事件
- `story_memory_query`：统一查询项目中的结构化创作记忆
- `story_memory_verify_continuity`：对草稿做连续性检查

`story_memory_query` 目前支持这些 `query_kind`：

- `characters`
- `events`
- `foreshadows`
- `chapters`
- `scenes`
- `world_rules`
- `locations`
- `style`
- `continuity_issues`

这些工具的设计原则是：

- 明确 project scope
- 结构化输入输出
- 输出中始终说明影响了哪个项目
- 不复用 `memory_write` 写小说 canon

当前实现还有两个重要约束：

- `story_memory_upsert_scene` 要求目标章节已经存在；第一版不会隐式创建空章节
- 连续性问题的默认闭环是 `open -> accepted | resolved | wont_fix`，不会删除历史问题记录

## 7. 当前 UI 能看到什么

第一版 UI 重点是浏览和绑定，而不是完整编辑器。

当前项目详情页可以查看：

- 项目标题与简介
- 角色数量、章节数量、未解决伏笔数量、连续性问题数量
- 角色名称列表
- 章节标题列表
- 未解决伏笔列表
- 连续性问题列表
- 时间线列表

这足够支持：

- 选择正确项目
- 确认当前会话使用了哪个故事上下文
- 快速检查是否存在未回收伏笔或连续性风险

## 8. 与长期记忆的边界

建议按下面的规则使用两套系统：

- 用长期记忆保存你作为用户的稳定偏好，例如文风偏好、常用流程、协作习惯
- 用创作记忆保存故事内部事实，例如角色关系、世界规则、事件时间线

不要把小说世界观、人设和章节事件手动写进长期记忆；这会让不同作品互相污染，也会让检索边界变得模糊。

## 9. 当前限制

当前版本仍有几个明确限制：

- 角色和项目编辑界面还是第一版，侧重展示而不是深度编辑
- 自动抽取剧情事件的后台工作流还只是预留入口
- 风格学习、版本归档、retcon 管理还没有完整 UI
- 还没有针对创作记忆建立独立 UI 自动化测试

这些限制不影响第一版把项目级故事记忆接进主聊天循环，但会影响高级创作工作流的舒适度。

## 10. 推荐使用方式

一个实用的工作流如下：

1. 为每部小说建立单独的 `WritingProject`
2. 在进入写作会话前先绑定当前项目
3. 先记录章节，再记录章节下的场景，保证场景衔接和上一场景检索稳定
4. 让 Claude 通过 story-memory 工具维护角色、规则、地点、伏笔和风格，而不是把关键信息散落在普通聊天文本里
5. 在写新章节或改稿前先运行连续性检查，并在处理后更新连续性问题状态
6. 只把用户偏好写入长期记忆，不把故事 canon 写入 `memory.md`

如果后续继续增强，这套创作记忆可以自然扩展到大纲规划、章节拆分、伏笔追踪和角色弧线分析等更完整的写作工作流。
