# Block 高度未自动刷新 Bug

**报告日期**: 2026-03-08
**严重程度**: 中
**状态**: 已修复

## 问题描述

在编辑器中初次打开会话或调整视图大小时，block 的高度没有自动刷新以适应内部内容的高度。需要手动聚焦后才会触发高度更新。

## 复现步骤

1. 打开一个新会话或切换到已有会话
2. 观察包含内容的 block，其高度可能不正确
3. 调整窗口/视图大小
4. block 高度仍然未适应内容
5. 点击聚焦到 block 后，高度才正确刷新

## 预期行为

- 初次打开会话时，block 应自动计算并设置正确高度
- 调整视图大小时，block 应自动重新计算高度
- 无需手动聚焦即可正确显示内容

## 实际行为

- block 高度在初次加载或视图调整后未更新
- 需要聚焦交互后才会刷新

## 可能原因

- ResizeObserver 未正确触发或未设置
- 初始化时机问题，内容未完全渲染时计算了高度
- 缺少视图变化时的响应式更新
- CSS 样式计算依赖焦点状态

## 解决方案

**修复日期**: 2026-03-08

### 修改内容
- 在 `updateNSView` 中添加了延迟高度计算，确保在布局完成后重新计算
- 添加了宽度追踪机制 (`lastKnownWidth`)，检测窗口大小变化
- 为 NSScrollView 添加了 `NSView.frameDidChangeNotification` 观察器，响应窗口调整
- 改进了 `recalculateHeight` 函数，当宽度变化时强制重新计算高度

### 修改文件
- `agentGui/Views/Editor/BlockTextEditor.swift`

### 修复说明
问题的根本原因是：
1. `updateNSView` 在视图布局完成前就被调用，导致高度计算不准确
2. 窗口大小变化时，没有触发块的高度重新计算

通过以下方式修复：
1. **延迟计算**：使用 `DispatchQueue.main.async` 在下一个运行循环中重新计算高度
2. **宽度追踪**：Coordinator 记录上次计算的宽度，当宽度变化超过 1 像素时强制重新计算
3. **帧变化通知**：添加 NSView.frameDidChangeNotification 观察器，确保窗口调整时触发高度更新
