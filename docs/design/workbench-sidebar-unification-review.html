Workbench Sidebar 风格统一审稿稿

基准完全取自 SessionListView：顶部 10pt 外边距、30pt 控件高度、12pt 控件圆角、轻玻璃材质、统一卡片半径与一致的列表密度。其余 panel 不改业务逻辑，只把容器层、header、section surface、按钮层级和空态视觉归一到同一套语言。

本稿重点

不是重做交互，而是把“像不同产品拼起来”的 panel 收束成同一套 sidebar shell。你可以直接点左侧顶部 tab 查看每个 panel 的迁移后效果。

统一规则

  • 所有 panel 共用同一层外壳：顶部导航下方直接进入 panel header，再进入内容区。
  • header 只允许两种构型：搜索栏 + 辅助动作，或标题栏 + 辅助动作。
  • 列表与卡片统一使用 16-20pt 圆角，不再混用裸 List、Form、ScrollView 默认背景。
  • 按钮层级固定为突出主操作、普通次操作、危险操作三档。
  • 空态保持 WorkbenchSidebarEmptyStateView 的语义，但放进同一 panel 节距系统。

各 panel 迁移策略

  • Workspace: 保留树视图逻辑，只收敛搜索区和 action bar 为单一 header 语言。
  • Git: 把现在偏“内嵌组件”的灰底盒子改成与 LSP 一致的分段卡片。
  • LSP: 保留信息密度，但卡片边距、标题层级、chips 规格全对齐。
  • Skills: 去掉 Form 默认 grouped 味道，切回 sidebar 专用卡片列表。
  • Diagnostics: 去掉导航页感，改成和其他 panel 一样的 section stack。

Token 摘要

项值
外层 padding10
控件高度30
控件圆角12
卡片圆角16
内容节距10
选中态accent 低饱和填充 + 细描边

我建议你重点确认

  • 顶部 header 是否都采用同一密度，而不是每个 panel 自己定义高度。
  • Git 和 Diagnostics 是否接受从“系统 List/Form”转向“自定义卡片列表”。
  • Skills 是否要完全向 Session 风格靠拢，而不是保留设置页语义。
  • LSP 是否维持当前信息量，还是趁这次一并压缩文案密度。
