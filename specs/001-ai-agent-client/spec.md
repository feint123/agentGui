# 功能规格说明：AI Agent 客户端

**功能分支**: `001-ai-agent-client`
**创建日期**: 2026-02-10
**状态**: 草稿
**输入**: 用户描述: "我的需求是开发一个ai agent的客户端。通过agent client protocol调用agent服务，如claude code、opencode 等等。我已经引入了第三方库 swift-acp ，他的使用方法在他的README文件中有详细说明。这是一个面向用户的功能完整的应用，要有作为一个程序的app所具备的基本能力和交互。"

## 假设与前提

基于 swift-acp SDK 文档，我们假设：
- 目标平台为 macOS 26.0+
- 支持通过 ACP 协议连接多种 AI 编程代理（Claude Code、OpenCode 等）
- 支持本地 stdio 和网络 WebSocket 两种连接方式
- 应用需要处理文件访问、终端操作等代理请求的权限管理

## 用户场景与测试 *(必填)*

### 用户故事 1 - 连接和管理 Agent (优先级: P1)

用户能够添加、配置和启动 AI Agent 服务，建立与 Agent 的通信会话。

**为什么是这个优先级**: 这是应用的核心功能，没有能够连接和通信的 Agent，其他所有功能都无法使用。

**独立测试**: 可通过启动一个本地 Agent（如 Claude Code）并成功创建会话来独立验证，用户可以看到 Agent 已连接并可用。

**验收场景**:

1. **假设** 用户首次启动应用，**当** 用户添加本地 Agent 路径（如 `/usr/local/bin/claude-code`），**则** Agent 被添加到列表并显示为"未连接"状态
2. **假设** Agent 已添加且处于未连接状态，**当** 用户点击"连接"按钮，**则** 应用启动 Agent 进程并显示连接成功状态，同时显示 Agent 的名称和版本信息
3. **假设** Agent 连接失败，**当** 启动过程发生错误（如路径错误、进程退出），**则** 显示友好的错误提示信息，指导用户解决问题
4. **假设** Agent 已连接，**当** 用户点击"断开"按钮，**则** 应用优雅地终止 Agent 进程并更新状态为未连接

---

### 用户故事 2 - 发送提示并接收响应 (优先级: P1)

用户能够向 Agent 发送文本提示，并实时查看 Agent 的响应内容，包括流式文本、工具调用和执行进度。

**为什么是这个优先级**: 这是用户与 Agent 交互的核心方式，实现提示发送和响应接收才能发挥 Agent 的价值。

**独立测试**: 可通过连接一个可用的 Agent，发送简单提示（如"解释这个文件"），验证响应能够正确显示。

**验收场景**:

1. **假设** Agent 已连接且会话已创建，**当** 用户在输入框输入文本并点击发送，**则** 提示内容显示在对话历史中，并显示"等待响应"状态
2. **假设** Agent 开始返回响应，**当** 响应以流式方式到达，**则** 文本内容实时追加显示，提供流畅的阅读体验
3. **假设** Agent 执行工具调用（如读取文件），**当** 工具调用事件到达，**则** 显示工具调用的类型、状态和相关内容（如文件路径、修改内容）
4. **假设** Agent 完成响应，**当** 响应结束，**则** 显示完成标记，并允许用户发送新的提示
5. **假设** 响应过程中出现错误，**当** Agent 返回错误信息，**则** 在对话中以醒目方式显示错误内容

---

### 用户故事 3 - 权限管理 (优先级: P2)

用户能够审查和批准 Agent 发起的敏感操作请求，如文件读写、终端命令执行等。

**为什么是这个优先级**: 涉及用户数据安全和系统安全，必须在 Agent 执行敏感操作前获得用户明确授权。

**独立测试**: 可通过发送需要文件访问的提示（如"读取某个文件"），验证权限请求对话框正确显示并处理用户的批准/拒绝操作。

**验收场景**:

1. **假设** Agent 请求读取文件，**当** 权限请求到达，**则** 显示权限请求对话框，包含操作类型、目标路径和请求原因
2. **假设** 权限请求对话框显示中，**当** 用户点击"允许"，**则** 请求被批准并传递给 Agent，操作继续执行
3. **假设** 权限请求对话框显示中，**当** 用户点击"拒绝"，**则** 请求被拒绝，Agent 收到拒绝响应
4. **假设** 多个权限请求连续到达，**当** 用户处理一个请求，**则** 下一个请求按顺序显示，或提供"全部允许"/"全部拒绝"选项
5. **假设** 用户之前批准过类似请求，**当** 相同类型请求再次到达，**则** 应用记住用户选择并自动批准（可在设置中配置）

---

### 用户故事 4 - 会话历史和项目管理 (优先级: P2)

用户能够创建多个会话，每个会话关联不同的工作目录，并能在会话间切换。

**为什么是这个优先级**: 用户通常同时处理多个项目，需要为每个项目维护独立的对话历史和上下文。

**独立测试**: 可通过创建两个不同工作目录的会话，发送提示后切换会话，验证每个会话保持独立的历史记录。

**验收场景**:

1. **假设** 应用已启动，**当** 用户选择工作目录并创建新会话，**则** 新会话出现在侧边栏，并激活为当前会话
2. **假设** 存在多个会话，**当** 用户点击侧边栏中的另一个会话，**则** 主视图切换到该会话的历史记录
3. **假设** 会话包含对话历史，**当** 用户切换回之前的会话，**则** 历史记录完整保留，包括所有提示和响应
4. **假设** 用户希望重新开始，**当** 用户点击"清除历史"或"新建会话"，**则** 创建新的空白会话，旧会话仍可访问
5. **假设** 应用关闭后重新打开，**当** 应用启动，**则** 之前的会话列表和历史记录恢复显示

---

### 用户故事 5 - 设置和偏好 (优先级: P3)

用户能够配置应用偏好，包括主题、自动批准策略、Agent 默认参数等。

**为什么是这个优先级**: 提升用户体验，允许用户根据个人习惯自定义应用行为。

**独立测试**: 可通过打开设置面板，修改各项配置并验证设置生效。

**验收场景**:

1. **假设** 用户打开设置面板，**当** 用户切换主题（浅色/深色/自动），**则** 应用界面立即反映主题变化
2. **假设** 用户配置自动批准策略，**当** 用户设置"自动批准文件读取操作"，**则** 文件读取权限请求不再弹出对话框，自动批准
3. **假设** 用户配置 Agent 默认参数，**当** 用户创建新会话，**则** 配置的参数（如默认模型、工作目录）自动应用
4. **假设** 用户配置启动行为，**当** 应用启动，**则** 根据配置决定是否自动连接上次使用的 Agent

---

### 用户故事 6 - Agent 注册表和发现 (优先级: P3)

用户能够浏览、搜索和安装来自 ACP 注册表的可用 Agent，无需手动配置路径。

**为什么是这个优先级**: 降低使用门槛，让用户能够方便地发现和尝试新的 Agent。

**独立测试**: 可通过打开 Agent 注册表面板，搜索特定 Agent 并模拟安装过程来验证。

**验收场景**:

1. **假设** 用户打开 Agent 注册表面板，**当** 面板加载完成，**则** 显示可用的 Agent 列表，包括名称、描述和版本信息
2. **假设** Agent 列表显示中，**当** 用户在搜索框输入关键词，**则** 列表过滤显示匹配的 Agent
3. **假设** 用户选择一个 Agent，**当** 用户点击"安装"按钮，**则** 显示安装进度，完成后 Agent 添加到本地列表
4. **假设** Agent 已安装，**当** 有新版本可用，**则** 在 Agent 列表显示更新提示
5. **假设** 安装过程失败，**当** 网络错误或权限不足，**则** 显示具体的错误信息和解决建议

---

### 边缘情况

- 当 Agent 进程意外崩溃或终止时，应用应检测到并通知用户，提供重新连接选项
- 当网络连接中断（WebSocket 连接），应用应自动尝试重连，超过重试次数后通知用户
- 当用户发送超大提示或 Agent 返回超大响应，应用应正确处理而不崩溃，显示内容摘要或分页
- 当权限请求长时间未响应（用户未操作），Agent 请求应超时并返回错误
- 当磁盘空间不足时，应用应警告用户并限制会话历史记录的存储
- 当 Agent 返回格式错误的响应，应用应记录错误并尝试恢复会话

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统 MUST 允许用户添加、编辑和删除 Agent 配置，包括名称、路径、连接类型（本地/远程）
- **FR-002**: 系统 MUST 支持通过 stdio 启动本地 Agent 进程
- **FR-003**: 系统 MUST 支持通过 WebSocket 连接远程 Agent 服务
- **FR-004**: 系统 MUST 支持 Agent 生命周期管理（启动、初始化、连接、断开、终止）
- **FR-005**: 系统 MUST 在 Agent 启动后执行初始化握手，交换能力和认证信息
- **FR-006**: 系统 MUST 支持基于令牌或 API 密钥的 Agent 认证
- **FR-007**: 系统 MUST 允许用户创建多个会话，每个会话关联独立的工作目录
- **FR-008**: 系统 MUST 支持向 Agent 发送文本提示
- **FR-009**: 系统 MUST 实时显示 Agent 的流式响应内容
- **FR-010**: 系统 MUST 显示 Agent 执行的工具调用，包括类型、状态、进度和结果
- **FR-011**: 系统 MUST 在 Agent 请求敏感操作时显示权限请求对话框
- **FR-012**: 系统 MUST 记住用户的权限批准决定，支持"记住此选择"选项
- **FR-013**: 系统 MUST 持久化会话历史记录，应用重启后恢复
- **FR-014**: 系统 MUST 提供设置面板，允许用户配置应用偏好
- **FR-015**: 系统 MUST 支持浅色/深色主题切换
- **FR-016**: 系统 SHOULD 提供浏览和安装 ACP 注册表 Agent 的能力
- **FR-017**: 系统 MUST 在错误发生时显示友好的错误消息和解决建议
- **FR-018**: 系统 MUST 支持取消正在进行的 Agent 请求
- **FR-019**: 系统 MUST 显示 Agent 的状态信息（连接状态、协议版本、支持的能力）
- **FR-020**: 系统 MUST 支持会话模式切换（如代码模式、聊天模式、计划模式）

### 关键实体

- **Agent 配置**: 代表一个 AI Agent 服务，包含名称、可执行路径/URL、连接类型（本地stdio/远程WebSocket）、认证信息、默认参数、状态（未连接/连接中/已连接/错误）
- **会话 (Session)**: 代表与 Agent 的一次对话上下文，包含会话 ID、工作目录、创建时间、模式（代码/聊天/计划）、关联的 Agent 引用、消息列表
- **消息 (Message)**: 代表对话中的一条消息，包含方向（用户发送/Agent响应）、内容类型（文本/工具调用/思考）、时间戳、状态（发送中/已完成/错误）
- **工具调用 (ToolCall)**: 代表 Agent 执行的操作，包含工具类型（读取/编辑/执行/搜索等）、状态（进行中/成功/失败）、相关路径、执行结果、时间戳
- **权限请求 (PermissionRequest)**: 代表 Agent 的敏感操作请求，包含请求类型（文件读取/文件写入/终端执行等）、目标资源路径、时间戳、用户决定（允许/拒绝）、是否记住选择
- **应用设置 (AppSettings)**: 代表用户的偏好配置，包含主题模式、自动批准策略、启动行为、默认 Agent 选择、界面布局偏好

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**: 用户能够在 30 秒内完成从添加 Agent 到发送第一个提示的完整流程
- **SC-002**: Agent 响应内容的显示延迟不超过 100ms（从接收到渲染）
- **SC-003**: 应用能够处理至少 10 个并发会话而不出现性能下降
- **SC-004**: 权限请求对话框在 200ms 内显示，确保用户能够及时响应
- **SC-005**: 应用启动时间不超过 2 秒（包含会话历史恢复）
- **SC-006**: 90% 的用户能够在首次使用时无需查阅文档完成基本操作（添加 Agent、发送提示）
- **SC-007**: 单个会话支持至少 1000 条消息历史记录而不影响浏览性能
- **SC-008**: Agent 意外断开后，应用能够在 5 秒内检测到并通知用户
